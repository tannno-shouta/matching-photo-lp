# 投稿タイプ定義 — 福岡垢抜けマッチングフォト

各投稿は以下のいずれか 1 タイプに属する。`config.json` の `typeMix` で配分を制御。
**5タイプ構成**：alpha=Attention/Interest, beta=Desire, gamma=Action入口, delta=Action, epsilon=信頼構築（Tips保存型）。

## 全タイプ共通：三層構造を意識する

| 層 | 何を語るか | 比喩素材 | メリット辞書 |
|---|---|---|---|
| 表層・中層（7〜8割） | 写真・垢抜けの直接効果 | 家・服・店構え・名刺・料理人 | いいね↑/マッチ率↑/返信率↑/初回デート率↑ |
| 深層（2〜3割） | 関係性・自信・ライフスタイル | 美容室の帰り道・整っている人の姿勢 | 自信↑/関係継続↑/選択肢↑ |

## 全タイプ共通：文体ルール（厳守）

- **基本です・ます調**：丁寧で誠実な案内人の温度（persona.md 参照）
- **体言止めを2〜3文に1回混ぜる**：全文「〜です」で単調にしない
- **定型句の連発禁止**：「一覧画面」「指が止まる」を毎回使わない（1投稿1回まで）。言い換え：スルーされる／開いてもらえる／スワイプの一瞬／流し見される
- **心理フックが基本形**：読者の内心の台詞を「" "」で引用してフックにする（persona.md の「心理フック」参照）
- **具体を最低1つ**：数字・場面・行動・台詞のどれかを必ず入れる
- **ポエム調禁止**：短文＋改行の連続で全体を構成しない。1ブロック2〜3文の地の文を混ぜる
- **NG**：「マジで」「〜じゃん」「俺も〜だった！」（痛いカジュアル）
- **OK**：「〜てる」「〜になる」「〜と思う」「〜という話」

## alpha

【心理フック・観察型】（AIDA: Attention + Interest）

**役割**: 読み手の内心を言い当てて注意を止め、「自分のことだ」と気づかせる。

**構造テンプレ**:
```
[1] フック：内心の台詞引用（"〜"）を基本に、比喩（家・服・店構え・料理人）や衝撃統計（「判断は1〜3秒」等、prompt-context の客観データ辞書から）も可
[2] 言い当て / ズレの指摘（「順番が逆」「見られてるのはそこじゃない」）
[3] 気づき（具体的な情景・数字と一緒に）
```

**ルール**:
- URL 一切禁止、ハッシュタグ禁止、サービス名禁止
- 客観メリット辞書から1〜2個まで滲ませる（並列羅列は beta の役割）
- 押し付け説教はNG。読み手に判断させる構造で

**例文（表層）**:
```
"プロフィール文はちゃんと書いたのに"
という人ほど、読まれる前に写真でスルーされています。

スワイプの一瞬に見られているのは、文章ではなく写真だけ。人柄が伝わるのは、開いてもらえた後です。
```

**例文（深層・自信/関係性）**:
```
美容室帰りに姿見の前で立ち止まる、あの感覚。
"今日ちょっといいかも" が積み重なると、姿勢も写真の表情も変わってきます。

垢抜けの効果は、写真の中だけで終わりません。
```

## beta

【ペイン直撃 → ベネフィット羅列型】（AIDA: Desire）

**役割**: ペインを名指して鏡になり、写真・垢抜けに投資するメリットを並べて欲求を立ち上げる。

**構造テンプレ（PAS）**:
```
[1] Problem（ペイン名指し）：「いいねが0で止まっている」「プロフィール文を磨こうとする」
[2] Agitate：「それは順番が違う」「プロフィール文は開いてもらえた人にしか読まれない」
[3] Solution（ベネフィット羅列）：
   ・いいね数↑
   ・マッチ率↑
   ・返信率↑
   ・初回デート率↑
[4] 締め＝ソフト紹介（必須）：「福岡なら、撮る前から整えるサービスもあります。」の温度で1行だけ
```

**バリエーション：OK/NG対比型**（保存されやすい）
```
[1] ペイン or 内心の台詞フック
[2] NG → 理由 ／ OK → 理由（必ず対にして、理由を付ける）
[3] 締め＝ソフト紹介（必須・上と同じ）
```

**ルール**:
- **締めに1行だけソフト紹介を必ず入れる**：「福岡なら〜というサービスもあります」と第三者に薦める温度で。自分語り・押し売り語（今すぐ／予約して／DM歓迎）は禁止
- LP URL は出さない（明示CTAは gamma/delta の役割）
- 「素材」「垢抜け」「入口」など固有語彙を使ってよい（連発しない）
- URL 禁止、ハッシュタグ禁止
- 箇条書き（・/→）でメリットを整理する

**例文（表層）**:
```
"マッチしないのは中身を見られてないから" と思って、自己紹介文を磨き続けるのは、順番が逆のことが多いです。

写真が変わると、こう動きます。
・いいね数↑
・マッチ率↑
・返信率↑

文章が読まれるのは、印象が良かった時だけ。
福岡なら、撮る前から整えるサービスもあります。
```

**例文（深層・差別化）**:
```
"プロに撮ってもらったのに増えなかった"
という相談が、実は一番多いです。

原因は撮影技術ではなく素材の方。服・髪・眉・表情が整っていないまま画質だけ上がると、粗まで鮮明になります。

整える順番は、撮る前から。福岡だと、そこまでやるサービスもあります。
```

## gamma

【価値先出し→軽い紹介】（AIDA: Action 入口）

**役割**: 「失敗例→なぜ→解決」で価値を出し切ってから、最後に1行だけ「福岡なら〜があるよ」と紹介して LP へ誘導。

**構造テンプレ**:
```
[1] 失敗例：うまくいってない状態を具体で描く（"いいね来ない" 写真の共通点など）
[2] なぜ：理由をロジックで解説（1〜2文）
[3] 解決：どうすれば変わるかを1文で
[4] 紹介：「福岡なら、撮る前の垢抜けから整えるサービスもある↓」+ LP URL
```

**ルール**:
- **URL込みで全体130字以内を目安**（URLだけで27字使う。失敗例・なぜ・解決は各1文に圧縮）
- **紹介は最後の1行だけ**。第三者に薦める温度で書く（「自分がやってる」と自分語りしない）
- 解決まで読んだだけで価値が完結する内容にする（紹介を消しても成立する投稿）
- LP URL 最大1つ、ハッシュタグ最大1個（使わなくてもよい）
- 押し売り語（今すぐ／予約／DM歓迎／残り◯枠）禁止

**例文**:
```
"プロフ文、ちゃんと書いたのに"
その文、読まれる前に写真でスルーされています。判断は1〜3秒。読まれるのは、印象が良かった時だけ。

マッチングは、写真が9割です。

福岡なら、垢抜けから整えて撮るサービスがあります↓
matching-photo-lp.vercel.app
```

```
"見た目じゃなくて性格で勝負したい"
これを言ってる時点で、性格で勝負できる性格じゃありません。見た目を整えるのは相手への配慮。その配慮ができない性格、ということです。

福岡なら、垢抜けから整えて撮るサービスがあります↓
matching-photo-lp.vercel.app
```

## delta

【ペイン→価値→軽い紹介・週 1 まで】（AIDA: Action）

**役割**: ペインを名指しして「なぜ・何が変わるか」を見せてから、最後に1行「福岡なら〜がある」で LP 誘導。gamma より一歩だけ踏み込む。

**構造テンプレ**:
```
[1] 失敗例 or ペイン名指し（"いいね一桁" / "写真変えたのに増えない"）
[2] なぜ / 何が変わるか（箇条書き2〜3個 可）
[3] 紹介：「福岡なら、撮る前の垢抜けから整えるサービスもある↓」+ LP URL
```

**ルール**:
- **URL込みで全体130字以内を目安**（箇条書きは2〜3個・各項目短く）
- **紹介は最後の1行だけ**。第三者に薦める温度（自分語りしない）
- 景表法 NG 表現禁止（絶対 / 必ず / 保証 / 100% / 誰でも / 最強 / 最高）
- 数値主張は「〜という傾向がある」「〜と言われている」程度に抑える
- URL 1 つまで、ハッシュタグ最大 1 個
- 押し売り語（今すぐ／予約／DM歓迎／残り◯枠）禁止

**例文（表層訴求）**:
```
"写真変えたのに増えない" のは、撮り方ではなく素材が原因のことが多いです。

服・髪・眉・表情。ここが整うと、
・開いてもらえる回数が増える
・マッチ後の会話も続く

福岡なら、そこから一緒に整えるサービスがあります↓
matching-photo-lp.vercel.app
```

**例文（深層訴求・自信/関係性）**:
```
"会えたのに続かない" は、写真と実物のギャップが原因のことが多いです。

加工で盛るほど初対面で損をします。素材（服・髪・眉）ごと整えた写真は、会ってからが強い。

福岡なら、撮る前の垢抜けからやるサービスがあります↓
matching-photo-lp.vercel.app
```

## epsilon

【実用Tips・保存型】（信頼構築・売り込みゼロ）

**役割**: 具体的なノウハウで「保存したくなる」投稿を作り、売り込みなしで信頼を貯める。

**構造テンプレ**:
```
[1] フック：内心の台詞（"〜"）or「NG3つ」型の予告 or 統計（客観データ辞書から）
[2] Tips本体：箇条書き2〜4個。各項目に短い理由を付ける
[3] 締め：一言の視点転換（押し売りなし・任意）
```

**ルール**:
- URL 禁止・サービス名禁止・ハッシュタグ禁止（信頼貯金に徹する）
- **箇条書き（・）のTipsを必ず2〜3個含める**。これがないものは epsilon ではない
- **全体で120字以内を目安**（フックは1行、各Tipの理由は10字前後で短く。詰め込みすぎない）
- 曜日テーマは「切り口」として使い、Tips 自体は服・髪・眉・表情・写真選び・プロフィールから出す
- OK/NG を対比するときは必ず「理由」を付ける
- 客観データ辞書の数字は入る場合のみ（無理に詰めない）

**例文（NG列挙型）**:
```
"どれを1枚目にすればいいか分からない"
という人は、まず避けるだけで変わるNG3つから。

・自撮り → 距離感が近すぎて圧が出る
・無表情 → 怖い印象になる
・数年前の写真 → 会った時のギャップで損

1枚目は他撮り・自然光・軽い笑顔が基本です。
```

**例文（統計フック型）**:
```
写真の判断は1〜3秒と言われています。その一瞬で見られているのは、顔の造形より「清潔感と雰囲気」です。

・髪：撮影の1週間以内に切る
・眉：整えるだけで印象が締まる
・服：無地でサイズの合ったもの

顔を変えるより、ここを整える方が早いです。
```
