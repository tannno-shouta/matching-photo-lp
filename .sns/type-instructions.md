# 投稿タイプ定義 — 福岡垢抜けマッチングフォト

各投稿は以下のいずれか 1 タイプに属する。`config.json` の `typeMix` で配分を制御。
**4タイプは AIDA ファネルに対応**：alpha=Attention/Interest, beta=Desire, gamma=Action入口, delta=Action。

## 全タイプ共通：三層構造を意識する

| 層 | 何を語るか | 比喩素材 | メリット辞書 |
|---|---|---|---|
| 表層・中層（7〜8割） | 写真・垢抜けの直接効果 | 家・服・店構え・名刺・料理人 | いいね↑/マッチ率↑/返信率↑/初回デート率↑ |
| 深層（2〜3割） | 関係性・自信・ライフスタイル | 美容室の帰り道・整っている人の姿勢 | 自信↑/関係継続↑/選択肢↑ |

## 全タイプ共通：文体ルール（厳守）

- **基本タメ口**：です・ます調は使わない
- **断言は体言止め**：「〜だ」「〜だよ」「〜だね」を抜く
- **心理フックが基本形**：読者の内心の台詞を「" "」で引用してフックにする（persona.md の「心理フック」参照）
- **具体を最低1つ**：数字・場面・行動・台詞のどれかを必ず入れる
- **ポエム調禁止**：短文＋改行の連続で全体を構成しない。1ブロック2〜3文の地の文を混ぜる
- **NG**：「マジで」「〜じゃん」「俺も〜だった！」（痛いカジュアル）
- **OK**：「〜てる」「〜になる」「〜と思う」「〜という話」

## alpha

【心理フック・観察型】（AIDA: Attention + Interest）

**役割**: 読み手の内心を言い当てて注意を止め、「自分のことだ」と気づかせる。

**構造テンプレ**:
```
[1] フック：内心の台詞引用（"〜"）を基本に、比喩（家・服・店構え・料理人）も可
[2] 言い当て / ズレの指摘（「順番が逆」「見られてるのはそこじゃない」）
[3] 気づき（具体的な情景・数字と一緒に）
```

**ルール**:
- URL 一切禁止、ハッシュタグ禁止、サービス名禁止
- 客観メリット辞書から1〜2個まで滲ませる（並列羅列は beta の役割）
- 押し付け説教はNG。読み手に判断させる構造で

**例文（表層）**:
```
"プロフィール文はちゃんと書いた"
って人ほど、読まれる前に写真で閉じられてる。

一覧でスワイプされる一瞬に見られてるのは、文章じゃなくて写真だけ。中身の勝負は、入口を抜けた後にしかない。
```

**例文（深層・自信/関係性）**:
```
美容室帰りに姿見の前で立ち止まる、あの感覚。
"今日ちょっといいかも" が積み重なると、姿勢も写真の表情も変わってくる。

垢抜けの効果は、写真の中だけで終わらない。
```

## beta

【ペイン直撃 → ベネフィット羅列型】（AIDA: Desire）

**役割**: ペインを名指して鏡になり、写真・垢抜けに投資するメリットを並べて欲求を立ち上げる。

**構造テンプレ（PAS）**:
```
[1] Problem（ペイン名指し）：「いいねが0で止まってる」「中身を磨こうとする」
[2] Agitate：「それは順番が違う」「中身は入口を抜けた人にしか届かない」
[3] Solution（ベネフィット羅列）：
   ・いいね数↑
   ・マッチ率↑
   ・返信率↑
   ・初回デート率↑
[4] 締め（タメ口・体言止め）
```

**ルール**:
- サービス名・LP URL は出さない（読み手に想起させる手前で止める）
- 「素材」「垢抜け」「入口」など固有語彙を使ってよい（連発しない）
- URL 禁止、ハッシュタグ禁止
- 箇条書き（・/→）でメリットを整理する

**例文（表層）**:
```
"マッチしないのは中身を見られてないから" と思って、自己紹介文を磨き続けるの、順番が逆のことが多い。

写真が変わると数字はこう動く。
・いいね数↑
・マッチ率↑
・返信率↑

文章が読まれるのは、写真で指が止まった後。
```

**例文（深層・差別化）**:
```
"プロに撮ってもらったのに増えなかった"
って相談が、実は一番多い。

原因は撮影技術じゃなくて素材の方。服・髪・眉・表情が整ってないまま画質だけ上がると、粗まで鮮明になる。

整える順番は、撮る前から。
```

## gamma

【サービス紹介・bio URL 誘導】（AIDA: Action 入口）

**役割**: サービスの構造（垢抜け＋撮る）を「他と違う理由」として紹介し、bio または LP へ誘導。

**構造テンプレ**:
```
[1] 構造の違いを提示（撮るだけ vs 垢抜け+撮る）
[2] 比喩で補強（料理人と食材、ヘアサロンと骨格診断、など）
[3] LP / LINE 相談誘導（bio）
```

**ルール**:
- LP URL を本文に出してOK（最大1つ）
- 「→ bio」「詳細はプロフィールリンクから」など bio 誘導も可
- ハッシュタグ最大 1 個（使わなくてもよい）
- CTAは具体ベネフィット明示型に：「LINEで相談、無料」など

**例文**:
```
"どの撮影サービスも同じに見える"
って言われるけど、構造は2種類しかない。

・撮るだけ → 素材はそのまま
・垢抜け＋撮る → 服・髪・眉から整える

自分がやってるのは後者。

→ matching-photo-lp.vercel.app
```

```
"撮り直したのに変わらなかった" って人と話すと、だいたい写真より前の段階でつまずいてる。

服・髪・眉・表情。ここが整ってないと、何回撮っても写真の上限は同じ。

そこから一緒に整えるのが自分の仕事。
→ bio から相談できる。
```

## delta

【サービス直接訴求・週 1 まで】（AIDA: Action）

**役割**: ペイン提示 → ベネフィット羅列 → サービスの構造的差別化 → LP 誘導。

**構造テンプレ**:
```
[1] ペイン名指し（マッチング停滞 / 写真変えても変わらなかった）
[2] ベネフィット羅列（客観メリット辞書から3〜5個）
[3] 差別化軸（垢抜け＋撮る、福岡）
[4] LP URL or LINE 誘導
```

**ルール**:
- 景表法 NG 表現禁止（絶対 / 必ず / 保証 / 100% / 誰でも / 最強 / 最高）
- 数値主張は「〜という傾向がある」「〜と言われている」程度に抑える
- 断定調を避け、提案調で
- URL 1 つまで
- ハッシュタグ最大 1 個

**例文（表層訴求）**:
```
"いいね一桁から動かない" なら、先に写真。

・いいね数↑
・マッチ率↑
・返信率↑

ただし撮るだけだと素材は変わらないから、自分は服・髪・眉・表情を整えてから撮る。福岡で活動してる。

→ matching-photo-lp.vercel.app
```

**例文（深層訴求・自信/関係性）**:
```
"会えたのに2回目がない" は、写真と実物のギャップが原因のことが多い。

加工で盛るほど初対面のハードルは上がる。自分は加工じゃなく、素材（服・髪・眉）を整えてから撮る。実物ごと良くなるから、会った後も続きやすい。

→ matching-photo-lp.vercel.app
```
